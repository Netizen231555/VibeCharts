# Extension registry contract and performance

API version is `1.0.0`. Incompatible API changes require a major version; compatible additions require a minor version, and compatible fixes a patch. Extensions declare an exact, `^`, `~`, or `>=` API range. State documents use version 2 and require chart context plus the registered extension's exact version, type, and schema version; there is no implicit migration. Storage and transfer belong to the host. The host must explicitly map context and anchors before transferring state to a different instrument, interval, source or view.
Import validation errors identify the import operation and extension ID as well as the invalid field when available; no instances are created on validation failure.

Register a trusted program object, create instances, dispose instances, then unregister the type; `disposeAll` is for chart destruction. Registration returns an `unregister` handle. An instance's `update` receives a complete replacement configuration. The context provides only the published chart capabilities and owns subscriptions and control removal callbacks created through it. The host supplies an accessible control area; its control implementation must supply visible focus, keyboard activation, semantic role and name, accessible errors and distinct slot names including their `barId`. Control activation must pass the selected ID, not a label. `resolveAnchor` returns an index coordinate or `null`, preserving the original anchor in configuration. A series config has `points`; a drawing config may contain `anchors` and price; an indicator config has `inputFields`, `units`, `outputs`, `points`, and optional `parameters`. Indicator factories provide `compute(points, parameters)` returning named arrays of `{barId, value}`; signals are display data only. Extension factories and lifecycle methods run as trusted host code, not in a sandbox. The registry performs no network, trading, storage or dynamic code evaluation.

An `unregister` handle is bound to its registration and cannot remove a later registration that reuses the same id.

Optional drawing-anchor `time` is an integer UTC Unix-millisecond value; invalid replacement configurations are rejected before the instance changes.
Indicator output timestamps, when present, must equal the corresponding declared input timestamp; the registry rejects fabricated or changed times.

Default button controls report synchronous activation failures through `onError` with the extension ID and `control-activate`, and show a text-only alert until a later successful activation. A custom DOM control owns its own accessibility and error presentation; the wrapped activation callback still reports and rethrows errors to it.
An instance descriptor's `renderable` boolean indicates whether its factory implementation supplies a `render` function. A host rendering loop calls `descriptor.render(...args)` only when `renderable` is true; the arguments and return value pass through unchanged to that function. Context `subscribe(event, handler)` returns the chart subscription's release function. `addControl` requires `id`, `name`, `role` and `onActivate`, accepts an optional `render`, and returns a release function.

Registration and lookup use maps; listing and disposal are linear in registrations or instances. Series and indicator validation depend on point count and timeline lookup cost, and host factory, rendering and computation costs are not bounded by the registry. No per-render registry scan is performed. Representative benchmarks, environment and thresholds are **unmeasured**; no performance target is claimed or considered met.
